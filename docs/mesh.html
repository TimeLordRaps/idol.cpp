Mesh conversion

idol::splats_to_mesh turns a set of splats into a triangle mesh in the same units as the splats. It is a port of the sprite pipeline's conversion, which is now part of the library.

Browser extraction and comparison

The local server now includes a Mesh tab. Generate a reconstruction or upload a saved Gaussian PLY file, then choose Generate mesh to preview and download the native OBJ output. Upload an original-model OBJ reference to compare geometry and download a JSON report. Set --mesh-executable when the built tool is outside the default build directories or executable search path.

The comparison samples each surface by triangle area and measures distance to the closest triangles of the other mesh, without alignment. It reports bidirectional mean distances, the larger directional 95th percentile, the sampled maximum, and F1 scores within recorded fractions of the reference bounding-box diagonal. F1 combines precision and recall by their harmonic mean. Source sampling limits coverage; these are agreement measurements, not ground-truth reconstruction accuracy. Use matching image, sampling, coordinate, and extraction settings.

The user guide records measured examples; the measurement record binds the source clouds, meshes, and tools by digest.

The pipeline

  1. Check the input. The options must be in range, the four columns must have the same length, and at least one splat must fall inside the grid.
  2. Scatter. Each splat adds its opacity, after a sigmoid, to the voxel that contains its centre. The grid has resolution voxels along each axis, covering [lo, hi]. Splats outside the grid are ignored. The sums run in float32, in splat order, on one thread, so the result does not depend on the thread count.
  3. Crop. Only the box of occupied voxels, plus the blur radius on every side, is kept. Outside that box the blurred density is zero, so the crop does not change the result.
  4. Blur. A separable Gaussian with sigma blur_sigma voxels, truncated at floor(4 σ + 0.5) voxels. Past the edge of the array the index is reflected back in, which is how scipy's gaussian_filter handles edges by default.
  5. Level. The surface sits at iso_fraction times the 99th percentile of the positive density values. The percentile is computed with linear interpolation, as numpy does.
  6. Marching cubes. Each grid cell is classified by which corners are at or above the level. Each grid edge that crosses the level gets one vertex, shared by the cells around it. Vertex positions are grid index × voxel size, offset to the grid's lower corner.
  7. Piece filter. Triangles are grouped into connected pieces by their shared vertices. Pieces with fewer than min_piece times the largest piece's faces are removed, and the vertices are renumbered.

Options

OptionDefaultCommand lineMeaning
lo, hi-0.55, 0.55--lo, --hiThe grid's extent on each axis. Must have hi > lo.
resolution176--resolutionVoxels per axis. Must be at least 2.
blur_sigma1.5--sigmaGaussian sigma in voxels. Must be positive.
iso_fraction0.2--isoLevel as a fraction of the 99th percentile density. Must be positive.
min_piece0.05--min-pieceSmallest kept piece, as a fraction of the largest piece's faces. Must not be negative.

Splat coordinates in the sprite pipeline sit inside about ±0.5, which is why the default grid covers ±0.55.

Output

idol::write_obj writes a Wavefront OBJ file: a v line for each vertex with six decimal places, then an f line for each triangle. Face indices are 1-based, as OBJ requires. The file is written as text, so it can be read by any mesh tool.

Verification

The unit tests check the blur against its closed form, check that a filled ball becomes a closed surface in which every edge is shared by two triangles with opposite orientation, check the piece filter and the percentile, and check the input rules. Against scikit-image:

  • Vertex positions agree with its classic marching-cubes output to about 10−7.
  • Vertex and face counts agree with the classic output.
  • Against the default Lewiner output, which the sprite pipeline used before this port, the face sets differ by 16 faces out of 205,116 on one sprite and by 468 out of 349,984 on another. Lewiner's rules for ambiguous cells were not ported, so cells with an ambiguous configuration can be split differently.

On the shapes the tests use, the surface is closed and consistently oriented. It is not guaranteed to match the Lewiner output face for face.
